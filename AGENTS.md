# android-notification-bridge

Forwards Android notifications to a macOS menu bar app while the phone screen is off and the phone is plugged in.

- `android/` - Kotlin app, no third-party runtime dependencies (tests use junit and org.json). `NotificationListenerService` -> `Forwarder` (single background thread) -> TCP to the Mac.
- `mac/` - SwiftPM package. `BridgeCore` (crypto, protocol) + `NotificationBridge` (SwiftUI `MenuBarExtra`, `LSUIElement`). `make build` assembles `build/Notification Bridge.app` and signs it with the first Developer ID in the keychain (hardened runtime), falling back to ad-hoc; `make install` copies to `~/Applications`. Keep a single installed copy: duplicate bundles with the same ID confuse LaunchServices.
- `testdata/vectors.json` - shared crypto test vectors; both test suites read it, proving interop. Generated by `testdata/generate.py` (uv script, OpenSSL via `cryptography`), an independent third implementation of the protocol; inputs are fixed so it's reproducible.
- `icons/` - source of truth for icons (designed by Byron). `make icons` at the repo root copies `icons/mac/AppIcon*.png` into `mac/Resources/Assets.xcassets/AppIcon.appiconset/` (compiled by `actool` during `make build` into `Assets.car` + `AppIcon.icns`), the menu bar PNGs into `mac/Resources/`, and `icons/android/res/` into `android/app/src/main/res/`. Never edit the copies. Menu bar icon is `MenuBarIcon.png` (18px) + `@2x` (36px), black on transparent, used as a template image.

## Protocol

- Discovery: Mac advertises Bonjour `_notifbridge._tcp` with TXT `pk` = base64 raw X25519 public key. Phone pins the first Mac key it sees.
- Connection per message. Frames are u32 big-endian length + payload (max 64 KiB).
- Frame 1 (hello): `0x01 || phone static pub (32) || ephemeral pub (32) || device name utf8`.
- Following frames: AES-256-GCM `nonce (12) || ciphertext || tag (16)` of JSON `{type: posted|removed, key, package, appName, title, text, ts}`.
- Key: HKDF-SHA256(ikm = DH(phone static, mac static) || DH(ephemeral, mac static), salt "notifbridge/1", info = phone pub || eph pub || mac pub).
- Mac replies one status byte per message: 0 delivered, 1 pending approval (buffered until allowed), 2 denied, 3 rejected (bad/stale >5 min).
- Changing crypto or framing requires updating and running `testdata/generate.py`, then updating both `Crypto.swift` and `Crypto.kt`.

## Building

- `make test` at the repo root runs both test suites.
- Mac: `cd mac && make test build`. SwiftPM's own sandbox must be disabled (`--disable-sandbox`, already in the Makefile); inside Claude's sandbox swift build still fails, so run unsandboxed.
- Android: `cd android && make test build`. `make install` / `make run` push the debug APK over `adb` (and launch it). `JAVA_HOME` defaults to `/opt/homebrew/opt/openjdk`. Gradle needs local socket binding (unsandboxed). compileSdk 37.2, minSdk 34.
- Known issue: notification banners show the generic app icon on Byron's Mac. The bundle icon is correct (Finder, System Settings); Notification Centre gets a stale entry from the iconservices persistent store, cached when the app first posted without an icon. Already tried: usernoted/NotificationCenter restart, relog, `~/Applications` install, asset catalog, Developer ID signing, version bump. Untried: `sudo rm -rf /Library/Caches/com.apple.iconservices.store` + reboot.
- Gate uses `EXTRA_PLUGGED`, not `isCharging`: Samsung battery protection stops charging at 80-85%.
